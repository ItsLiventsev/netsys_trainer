# netsys_trainer — интерактивные тренажёры по сетевым технологиям

Набор статических веб-симуляторов лабораторных работ для уроков по сетевым технологиям.
Все тренажёры сделаны в одной стилистике и с одной грамматикой взаимодействия: шаги с
прогрессом, панель инструментов, верстак со сценами, теория и чек-лист справа,
автоматический отчёт и 100-балльная шкала с отправкой оценки в МЭШ.

| № | Тренажёр | Тема | Путь |
| --- | --- | --- | --- |
| 01 | Обжим витой пары | прямой обжим Straight-Through, T568B, коннектор RJ-45, кримпер, кабельный тестер | [`simulators/twisted-pair/`](simulators/twisted-pair/) |
| 02 | Монтаж сетевых розеток | розетка RJ-45, модуль keystone (110 IDC), маркировка B, заделочный нож, сборка корпуса, тестер | [`simulators/network-socket/`](simulators/network-socket/) |

Корневой `index.html` — витрина со списком тренажёров.

- Статический сайт без сборки и без внешних CDN — работает на GitHub Pages и внутри `iframe`
  Московской электронной школы.
- Вся графика — SVG и CSS, шрифты — системные.
- В каждом тренажёре 7 этапов, два режима (тренировка и экзамен), выгрузка отчёта и
  отправка оценки через `postMessage`.

## Быстрый старт

```bash
# любой статический сервер из корня репозитория
python3 -m http.server 8000
# или
npm start          # node tools/serve.js → http://localhost:3000

# тесты (нужен Node 20+)
npm install
npm test
```

Открыть `http://localhost:8000/` — попадёте на витрину, оттуда в нужный тренажёр.

> Открывать `index.html` двойным щелчком (`file://`) не рекомендуется: часть браузеров
> блокирует `localStorage` и модули для локальных файлов. Любой http-сервер решает вопрос.

Сборщика нет намеренно: файлы подключаются обычными `<script>` в фиксированном порядке,
глобальные пространства имён — `AppCore`, `AppIcons`, `Shell`, `AppReportFactory`, а в каждом
тренажёре — `APP_DATA`, `APP_GFX`, `AppState`, `AppSteps`, `AppReport`, `App`. Такой вариант
одинаково хорошо работает из локальной папки, в iframe МЭШ и на GitHub Pages, и его не нужно
пересобирать после правок.

Порядок подключения одинаков в обоих тренажёрах:

```html
<script src="../../shared/js/core.js"></script>
<script src="../../shared/js/icons.js"></script>
<script src="../../shared/js/shell.js"></script>
<script src="../../shared/js/report.js"></script>   <!-- фабрика до report.js тренажёра -->
<script src="js/data.js"></script>
<script src="js/graphics.js"></script>
<script src="js/state.js"></script>
<script src="js/steps.js"></script>
<script src="js/report.js"></script>
<script src="js/app.js"></script>
```

### Как добавить третий тренажёр

1. Скопировать `simulators/network-socket` в `simulators/<имя>`.
2. Заменить `data.js` (шаги, инструменты, теория, тест), `graphics.js` (свой SVG-арт) и
   сцены в `css/sim.css`.
3. Переписать `state.js` (поля State, `readiness`, `computeScore`, `lmsPayload`) и `steps.js`
   (`render`/`mount` для каждого шага, `checklistStates`, `progress`).
4. В `report.js` описать таблицу и текст отчёта, в `app.js` — конфигурацию `Shell.init`.
5. Добавить карточку в корневой `index.html` и пару тестов в `tests/`.

Общая часть (оболочка, отчёт, иконки, drag&drop, тосты, store) переиспользуется без правок.

## Тренажёр 01. Обжим витой пары (T568B)

| Шаг | Что делает ученик | Что проверяет симулятор |
| --- | --- | --- |
| 1. Подготовка | перетаскивает кабель в стриппер, тянет рукоятку | длина зачистки 2,0–2,5 см (в тренировке иначе возврат) |
| 2. Раскладка | раскладывает 8 жил по позициям 1–8 | порядок T568B; неверная жила «пружинит» и возвращается |
| 3. Коннектор | ровняет и обрезает жилы, вставляет в RJ-45, ползунком доводит до 100% | жилы дошли до конца каналов, оболочка под зажимом |
| 4. Обжим | зажимает кримпер и удерживает до полного усилия | усилие обжима: <70% — контакты не прожаты, 70–90% — предупреждение |
| 5. Второй конец | повторяет шаги 1–4 для конца B | тот же стандарт; иначе тестер покажет перекрёст |
| 6. Проверка | осматривает коннекторы, подключает тестер, запускает прогон | индикаторы 1–8 по порядку; перекрёст виден как 1-3, 2-6, 3-1, 6-2; обрыв — индикатор не горит |
| 7. Отчёт | отвечает на 5 вопросов, заполняет ФИО и вывод, выгружает отчёт | автоматическая таблица, баллы, оценка, отправка в МЭШ |

Баллы: порядок жил 30, качество обжима 25, работоспособность 20, отчёт 15, вопросы 10.

## Тренажёр 02. Монтаж сетевых розеток

| Шаг | Что делает ученик | Что проверяет симулятор |
| --- | --- | --- |
| 1. Инструменты | выбирает из набора нужное: стриппер, заделочный нож, бокорезы, модуль, корпус, стяжка, отвёртка | лишние инструменты (кримпер, коннектор RJ-45) и пропуски; в тренировке подсвечиваются сразу |
| 2. Подготовка | надевает кабель в стриппер, тянет рукоятку | длина зачистки 2,0–2,5 см, оболочка не перерезана; отдельно — ошибка «зачистил жилы» |
| 3. Разделка | перетаскивает 8 жил в контакты модуля по цветной маркировке B | соответствие «контакт → цвет»: 1 БО, 2 О, 3 БЗ, 4 С, 5 БС, 6 З, 7 БК, 8 К; неверная жила возвращается |
| 4. Заделка | вдавливает жилы заделочным ножом по одной или весь ряд сразу | все 8 контактов IDC заделаны; попытка «заделать кримпером» фиксируется как ошибка |
| 5. Сборка | ставит стяжку, вщёлкивает модуль в корпус, закручивает два винта рамки | оболочка зафиксирована, модуль в корпусе, рамка прикручена; перетянутые винты — предупреждение |
| 6. Проверка | осматривает контакты, подключает тестер, запускает прогон | 8 индикаторов; перекрёст, обрыв, зачищенные жилы — видны на тестере |
| 7. Отчёт | отвечает на 5 вопросов, заполняет ФИО и вывод, выгружает отчёт | таблица разделки, баллы, оценка, отправка в МЭШ |

Баллы: разделка по маркировке B 30, качество монтажа 25 (набор 3, зачистка 4, заделка 8,
стяжка 3, модуль 4, винты 3), работоспособность 20, отчёт 15, вопросы 10.

Режимы (в обоих тренажёрах):

- **Тренировка** — ошибки видны сразу: неверная жила возвращается, слишком длинная зачистка
  отклоняется, лишний инструмент подсвечивается.
- **Экзамен** — без «страховок»: действия фиксируются как есть, а последствия видны на
  тестере и в отчёте.

## Оценивание (100 баллов)

Одинаковая шкала и одинаковая структура в обоих тренажёрах:

| Раздел | Баллы | Как считается |
| --- | --- | --- |
| Правильность монтажа | 30 | тренажёр 01 — порядок жил (15 за конец); тренажёр 02 — разделка по маркировке (по 3,75 за жилу) |
| Качество | 25 | 01: оболочка под зажимом, глубина вставки, усилие обжима; 02: набор, зачистка, заделка, стяжка, модуль, винты |
| Работоспособность | 20 | по результату тестера: все 8 жил и прямой порядок — 20, обрывы и перекрёст — пропорционально |
| Оформление отчёта | 15 | ФИО и группа (4), вывод ≥ 40 символов (4), тест пройден (4), отчёт выгружен/скопирован (3) |
| Ответы на вопросы | 10 | 5 вопросов × 2 балла |

Оценка: 90–100 — «Отлично», 75–89 — «Хорошо», 60–74 — «Удовлетворительно», ниже 60 —
«Неудовлетворительно». Баллы пересчитываются на каждом шаге и видны в шапке и в панели
«Ход работы». Эталонные прогоны обоих тренажёров (без выгрузки файла отчёта) дают
**97/100**: 3 балла за выгрузку или копирование отчёта начисляются отдельно, то есть
максимум 100 набирается только вместе с сохранённым отчётом.

## Интеграция с МЭШ

### Изоляция и встраивание

- Ни одного внешнего запроса: шрифты системные, графика — SVG, стили и скрипты локальные.
  Мета-тег CSP в каждой странице разрешает только `'self'`.
- `frame-ancestors` в `<meta>` браузеры игнорируют — для боевого хостинга пропишите
  **HTTP-заголовок** на сервере/CDN:

  ```http
  Content-Security-Policy: default-src 'self'; frame-ancestors 'self' https://school.mos.ru https://*.mos.ru
  ```

  `X-Frame-Options` лучше не выставлять вовсе или оставить `ALLOW-FROM`-совместимую политику:
  при `DENY`/`SAMEORIGIN` МЭШ не сможет показать страницу в iframe.
- Роутинг — только hash (`#/step/3`), серверный роутинг не нужен. Поэтому **любой** тренажёр
  можно встроить напрямую: `https://<user>.github.io/<repo>/simulators/network-socket/`.

### Обмен сообщениями

Страница отправляет в `window.parent`:

```js
{ type: 'LMS_SCORE', score: 97, maxScore: 100, percent: 97, grade: 5,
  gradeText: 'Отлично', work: 'Монтаж сетевой розетки RJ-45 (T568B)',
  simulator: 'network-socket', standard: 'T568B', completed: true,
  parts: { wiring: { value: 30, max: 30 }, quality: { value: 22, max: 25 }, ... },
  durationSec: 512, timestamp: '2026-10-29T08:00:00.000Z' }
```

Дополнительно поддерживаются сообщения от LMS:

| Входящее сообщение | Действие |
| --- | --- |
| `{ type: 'LMS_READY' }` (исходящее при загрузке) | сообщает `work`, `maxScore`, `simulator` |
| `{ type: 'LMS_REQUEST_SCORE' }` | страница отвечает текущим `LMS_SCORE` |
| `{ type: 'LMS_RESET' }` | сбрасывает прогресс |
| `{ type: 'LMS_SET_MODE', mode: 'training' \| 'exam' }` | переключает режим |

Оценка отправляется по кнопке «Завершить и отправить» (шаг 7). На принимающей стороне
обязательно проверяйте `event.origin` — на стороне тренажёра `targetOrigin` указан `'*'`,
чтобы работать в любом домене МЭШ.

### Сохранение

Прогресс лежит в `localStorage` под ключами `netsys.tp.state.v1` (обжим) и
`netsys.socket.state.v1` (розетки); версия схемы хранится в самом объекте, поэтому старые
записи безопасно игнорируются. Если хранилище недоступно (инкогнито, политики школы),
тренажёр показывает предупреждение и продолжает работать без сохранения.

## GitHub Pages

Деплой делает workflow `.github/workflows/pages.yml` при каждом пуше в `main`
(или вручную: **Actions → Deploy to GitHub Pages → Run workflow**).

**Обязательное условие — один раз включить Pages в настройках репозитория:**

1. **Settings** (вкладка репозитория) → **Pages**.
2. **Build and deployment → Source** = **GitHub Actions**.
3. **Save**. После этого любой пуш в `main` публикует сайт.

Адреса: витрина `https://<user>.github.io/<repo>/`, тренажёры — в подкаталогах
`simulators/twisted-pair/` и `simulators/network-socket/`.

### Если деплой упал

| Ошибка в логе | Причина и что делать |
| --- | --- |
| `Get Pages site failed. Please verify that the repository has Pages enabled…` | Pages не включён. Выполните шаги 1–3 выше и запустите workflow заново (**Re-run all jobs**). |
| `GitHub Pages не включён` (наша проверка) | То же самое, но с подсказкой: шаг `Проверить, что Pages включён` падает раньше и печатает инструкцию. |
| `Resource not accessible by integration` при создании Pages через API | У токена нет прав `administration`/`pages` — включите Pages руками в Settings, из workflow это не сделать с `GITHUB_TOKEN`. |
| `Deployment failed, try again later` / очередь | Повторный запуск: **Re-run all jobs**. Параллельные деплои схлопываются через `concurrency: pages`. |

Workflow сначала прогоняет `npm test` отдельной job — если тренажёры сломаны, сайт не публикуется.

Файл `.nojekyll` уже добавлен (и передаётся в артефакт через `include-hidden-files`): он отключает
обработку Jekyll и сохраняет все пути как есть. Ссылки на стили и скрипты относительные,
поэтому проект работает и из подкаталога. При использовании варианта *Deploy from a branch*
выберите `main` / `/ (root)`.

## Тестирование

```bash
npm install
npm test        # node tests/run-all.js — по очереди прогоняет все *.test.js
```

Что проверяют тесты на jsdom:

- страница тренажёра собирается без ошибок исполнения, стартовый балл — 0;
- отказ при неверной зачистке, возврат неверной жилы, приём верного набора инструментов;
- полный порядок T568B / разделка по маркировке B, заделка всех 8 контактов;
- начисление баллов по разделам, сохранение в `localStorage`;
- сквозной сценарий до отчёта: тестер исправен, мини-тест на 10, итог 97/100,
  `LMS_SCORE` с `completed: true`;
- отсутствие внешних сетевых запросов в подключённых файлах.

Ручной чек-лист перед публикацией:

1. **iframe в МЭШ** — нет ошибок CSP, `LMS_SCORE` приходит в родительское окно, прогресс
   сохраняется после перезагрузки.
2. **GitHub Pages** — витрина, оба тренажёра, иконка и все пути.
3. **Мобильный** — drag-and-drop пальцем, табы «Инструменты / Работа / Теория»,
   ничего не перекрывает верстак.
4. **Клавиатура** — все действия доступны без мыши (см. ниже).
5. **`prefers-reduced-motion`** — анимации отключаются, состояния меняются мгновенно.

## Доступность и клавиатура

- Зачистка: `←`/`→` — по 0,1 см, `Shift + ←/→` — по 0,5 см, `Home`/`End` — крайние
  значения, `Enter` — применить.
- Работа с жилами (раскладка в коннектор и разделка на модуле): `Enter` на жиле берёт её,
  стрелки двигают фокус по контактам, `Enter` ставит, `Esc` отменяет выбор. Контакт с жилой
  по нажатию возвращает её в пучок.
- Обжим: удерживайте `Space` или `Enter` на кримпере, пока усилие не дойдёт до 100%.
- Заделка: `Enter` на контакте — заделать один, кнопка «Заделать весь ряд» — все сразу.
- Модальные окна закрываются `Esc`, фокус замыкается внутри окна.
- Все результаты объявляются через `aria-live`; у слайдеров заданы `role="slider"` и
  `aria-valuetext`.

## Дизайн

Светлая тема: фон `#F8F9FA`, поверхности `#FFFFFF`, текст `#1F2937`, акцент `#3B82F6`,
скругления 8–18 px, мягкие тени. Цвета жил соответствуют стандарту: бело-оранжевый,
оранжевый, бело-зелёный, синий, бело-синий, зелёный, бело-коричневый, коричневый.
Все анимации — 140–340 мс на `transform`/`opacity`, при `prefers-reduced-motion` отключаются.

## Ограничения

- Симуляция детерминированная: нет физики кабеля, случайных дефектов и таймеров на шаг.
- Один стандарт на изделие (T568B) — по условию работы; T568A и кроссовер разобраны
  в теории и в тесте.
- Отчёт выгружается как `.txt` и печатается в PDF средствами браузера; серверной
  генерации PDF нет намеренно (статический хостинг).
- Тренажёр розеток не моделирует реальный кабель-тест на длину/затухание — только
  непрерывность и порядок пар.
