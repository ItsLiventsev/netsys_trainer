# Обжим витой пары — интерактивный тренажёр

Веб-симулятор лабораторной работы «Обжим витой пары» (прямой обжим, **T568B**): от снятия
оболочки и раскладки жил до обжима кримпером, проверки тестером и автоматического отчёта
с оценкой для МЭШ.

- Статический сайт без сборки и без внешних CDN — работает на GitHub Pages и внутри `iframe`
  Московской электронной школы.
- Вся графика — SVG и CSS, шрифты — системные.
- 7 этапов, два режима (тренировка и экзамен), 100-балльная шкала, выгрузка отчёта и
  отправка оценки через `postMessage`.

---

## Быстрый старт

```bash
# любой статический сервер из корня репозитория
python3 -m http.server 8000
# или
npm start          # node tools/serve.js → http://localhost:3000

# тесты (нужен Node 20+)
npm install
npm test
```

Открыть `http://localhost:8000/`.

> Открывать `index.html` двойным щелчком (`file://`) не рекомендуется: часть браузеров
> блокирует `localStorage` и модули для локальных файлов. Любой http-сервер решает вопрос.

    graphics.js             SVG: иконки, стриппер, кримпер, коннектор, схема жил, кольцо оценки

    drag.js                 Pointer Events + клавиатурные альтернативы
    ui.js                   тосты, модальные окна, степпер, чек-лист, теория, режимы
    steps.js                шаги 1–6: зачистка, раскладка, коннектор, обжим, тестер
    report.js               шаг 7: мини-тест, отчёт, баллы, экспорт, LMS

Сборщика нет намеренно: файлы подключаются обычными `<script>` в фиксированном порядке,
глобальные пространства имён — `APP_DATA`, `APP_GFX`, `AppState`, `AppDrag`, `AppUI`,
`AppSteps`, `AppReport`, `App`. Такой вариант одинаково хорошо работает из локальной папки,
в iframe МЭШ и на GitHub Pages, и его не нужно пересобирать после правок.

## Этапы и проверки

| Шаг | Что делает ученик | Что проверяет симулятор |
| --- | --- | --- |
| 1. Подготовка | перетаскивает кабель в стриппер, тянет рукоятку | длина зачистки 2,0–2,5 см (в тренировке иначе возврат) |
| 2. Раскладка | раскладывает 8 жил по позициям 1–8 | порядок T568B; неверная жила «пружинит» и возвращается |
| 3. Коннектор | ровняет и обрезает жилы, вставляет в RJ-45, ползунком доводит до 100% | жилы дошли до конца каналов, оболочка под зажимом |
| 4. Обжим | зажимает кримпер и удерживает до полного усилия | усилие обжима: <70% — контакты не прожаты, 70–90% — предупреждение |
| 5. Второй конец | повторяет шаги 1–4 для конца B | тот же стандарт; иначе тестер покажет перекрёст |
| 6. Проверка | осматривает коннекторы, подключает тестер, запускает прогон | индикаторы 1–8 по порядку; перекрёст виден как 1-3, 2-6, 3-1, 6-2; обрыв — индикатор не горит |
| 7. Отчёт | отвечает на 5 вопросов, заполняет ФИО и вывод, выгружает отчёт | автоматическая таблица, баллы, оценка, отправка в МЭШ |

Режимы:

- **Тренировка** — ошибки видны сразу: неверная жила возвращается в пучок, слишком длинная
  зачистка отклоняется, жилы нельзя оставить недожатыми.
- **Экзамен** — без «страховок»: жилы ставятся в любые позиции, глубина и качество обжима
  фиксируются как есть, а последствия видны на тестере и в отчёте.

## Оценивание (100 баллов)

| Раздел | Баллы | Как считается |
| --- | --- | --- |
| Правильность порядка жил | 30 | 15 за конец; в тренировке минус 3 за каждую ошибку раскладки, в экзамене — пропорционально верным позициям |
| Качество обжима | 25 | по 12,5 за конец: оболочка под зажимом (2,5), глубина вставки (5), усилие обжима (5) |
| Работоспособность | 20 | по результату тестера: все 8 жил и прямой обжим — 20, обрывы и перекрёст — пропорционально |
| Оформление отчёта | 15 | ФИО и группа (4), вывод ≥ 40 символов (4), тест пройден (4), отчёт выгружен/скопирован (3) |
| Ответы на вопросы | 10 | 5 вопросов × 2 балла |

Оценка: 90–100 — «Отлично», 75–89 — «Хорошо», 60–74 — «Удовлетворительно», ниже 60 — «Неудовлетворительно».

Баллы пересчитываются на каждом шаге и видны в шапке и в панели «Ход работы».

## Интеграция с МЭШ

### Изоляция и встраивание

- Ни одного внешнего запроса: шрифты системные, графика — SVG, стили и скрипты локальные.
  Мета-тег CSP в `index.html` разрешает только `'self'`.
- `frame-ancestors` в `<meta>` браузеры игнорируют — для боевого хостинга пропишите
  **HTTP-заголовок** на сервере/CDN:

  ```http
  Content-Security-Policy: default-src 'self'; frame-ancestors 'self' https://school.mos.ru https://*.mos.ru
  ```

  `X-Frame-Options` лучше не выставлять вовсе или оставить `ALLOW-FROM`-совместимую политику:
  при `DENY`/`SAMEORIGIN` МЭШ не сможет показать страницу в iframe.
- Роутинг — только hash (`#/step/3`), серверный роутинг не нужен.

### Обмен сообщениями

Страница отправляет в `window.parent`:

```js
{ type: 'LMS_SCORE', score: 87, maxScore: 100, percent: 87, grade: 4,
  gradeText: 'Хорошо', work: 'Обжим витой пары (Straight-Through, T568B)',
  standard: 'T568B', completed: true,
  parts: { order: { value: 30, max: 30 }, quality: { value: 22, max: 25 }, ... },
  durationSec: 512, timestamp: '2026-10-29T08:00:00.000Z' }
```

Дополнительно поддерживаются сообщения от LMS:

| Входящее сообщение | Действие |
| --- | --- |
| `{ type: 'LMS_READY' }` (исходящее при загрузке) | сообщает `maxScore` и версию работы |
| `{ type: 'LMS_REQUEST_SCORE' }` | страница отвечает текущим `LMS_SCORE` |
| `{ type: 'LMS_RESET' }` | сбрасывает прогресс |
| `{ type: 'LMS_SET_MODE', mode: 'training' \| 'exam' }` | переключает режим |

Оценка отправляется по кнопке «Завершить и отправить» (шаг 7). На принимающей стороне
обязательно проверяйте `event.origin` — на стороне тренажёра `targetOrigin` указан `'*'`,
чтобы работать в любом домене МЭШ.

### Сохранение

Прогресс лежит в `localStorage` под ключом `netsys.tp.state.v1` (версия схемы — в самом
объекте). Если хранилище недоступно (инкогнито, политики школы), тренажёр показывает
предупреждение и продолжает работать без сохранения.

## GitHub Pages

1. Запушьте репозиторий в GitHub.
2. **Settings → Pages → Build and deployment**: Source = *GitHub Actions* (workflow уже лежит
   в `.github/workflows/pages.yml`) либо *Deploy from a branch* → `main` / `/ (root)`.
3. Сайт будет доступен по адресу `https://<user>.github.io/<repo>/`.

Файл `.nojekyll` уже добавлен: он отключает обработку Jekyll и сохраняет все пути как есть.
Ссылки на стили и скрипты относительные, поэтому проект работает и из подкаталога.

## Тестирование

```bash
npm install
npm test
```

Дымовой тест на jsdom проверяет: сборку страницы без ошибок, стартовый балл, отказ при
неверной зачистке, возврат неверной жилы, полный порядок T568B, начисление баллов,
сохранение в `localStorage` и отсутствие внешних сетевых запросов.

Ручной чек-лист перед публикацией:

1. **iframe в МЭШ** — нет ошибок CSP, `LMS_SCORE` приходит в родительское окно, прогресс
   сохраняется после перезагрузки.
2. **GitHub Pages** — прямой заход на страницу, проверка иконки и всех путей.
3. **Мобильный** — drag-and-drop пальцем, табы «Инструменты / Работа / Теория»,
   ничего не перекрывает верстак.
4. **Клавиатура** — все действия доступны без мыши (см. ниже).
5. **`prefers-reduced-motion`** — анимации отключаются, состояния меняются мгновенно.

## Доступность и клавиатура

- Шаг кабеля в стриппер: `Enter` на кабеле → `Tab` до стриппера → `Enter`.
- Зачистка: `←`/`→` — по 0,1 см, `Shift + ←/→` — по 0,5 см, `Home`/`End` — крайние
  значения, `Enter` — применить.
- Раскладка жил: `Enter` на жиле берёт её, стрелки двигают фокус по слотам, `Enter`
  ставит, `Esc` отменяет выбор. Слот с жилой по нажатию возвращает её в пучок.
- Обжим: удерживайте `Space` или `Enter` на кримпере, пока усилие не дойдёт до 100%.
- Модальные окна закрываются `Esc`, фокус замыкается внутри окна.
- Все результаты объявляются через `aria-live`; у слайдера глубины и рукоятки зачистки
  заданы `role="slider"` и `aria-valuetext`.

## Дизайн

Светлая тема: фон `#F8F9FA`, поверхности `#FFFFFF`, текст `#1F2937`, акцент `#3B82F6`,
скругления 8–18 px, мягкие тени. Цвета жил соответствуют стандарту: бело-оранжевый,
оранжевый, бело-зелёный, синий, бело-синий, зелёный, бело-коричневый, коричневый.
Все анимации — 140–340 мс на `transform`/`opacity`, при `prefers-reduced-motion`
отключаются.

## Ограничения

- Симуляция детерминированная: нет физики кабеля, случайных дефектов и таймеров на шаг.
- Один стандарт на оба конца (T568B) — по условию работы; T568A и кроссовер разобраны
  в теории и в тесте.
- Отчёт выгружается как `.txt` и печатается в PDF средствами браузера; серверной
  генерации PDF нет намеренно (статический хостинг).
